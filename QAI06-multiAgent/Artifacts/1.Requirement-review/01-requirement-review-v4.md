## 2. Проект

| Параметр | Значение |
|---|---|
| Название проекта | Лендинг «Мини-маркет» (MVP) |
| Основное направление проекта | E-commerce / лендинг для проверки спроса и сбора заявок: витрина → корзина → заявка (без онлайн-оплаты) |
| Тип проекта | **Web** (адаптивное веб-приложение, mobile-first лендинг) |
| Код проекта | В требованиях **не указан** (DEF-19). Код не выдуман. |
| Владелец продукта | Product Owner |
| Бизнес-заказчик | Маркетинг / E-commerce |

**Контекст (§2):** нужен быстрый и недорогой MVP-лендинг для проверки спроса и сбора первых заказов; полноценный маркетплейс избыточен (нет логистики, платежей, продавцов). Минимальный путь: зашёл → авторизовался → выбрал товары → добавил в корзину → оформил заявку.

**Бизнес-цели и KPI (§3):**

| ID | Цель | Метрика успеха (KPI) |
|---|---|---|
| BG-1 | Проверить спрос на товары через лендинг | ≥ 100 оформленных заявок в первый месяц |
| BG-2 | Снизить барьер входа для покупателя | Конверсия «визит → авторизация» ≥ 25% |
| BG-3 | Обеспечить понятный путь покупки | Конверсия «корзина → заявка» ≥ 40% |
| BG-4 | Собрать контактные данные для повторных продаж | ≥ 80% заявок с валидным телефоном/email |

**Направления функциональности (по §4 и §6):** Авторизация; Каталог товаров; Карточка товара; Корзина; Оформление заявки. Вспомогательные: поиск/сортировка (опционально), адаптивность/SEO, логирование, базовая доступность.

### 5.1. §10 «Критерии приёмки MVP (бизнес-уровень)» — дословно

> MVP считается успешным, если:
> - Пользователь может пройти путь: каталог → авторизация → корзина → заявка без ошибок.
> - Все ключевые события логируются и доступны для анализа.
> - Лендинг корректен на мобильных и десктопе.
> - Заявки доходят до менеджера с валидными контактными данными.

### 5.2. Производный сценарий (НЕ документирован в требованиях)

- **UC-D1 (производный, ориентир, не требование):** посетитель открывает лендинг → просматривает каталог → открывает карточку товара → добавляет товары в корзину → переходит к оформлению → авторизуется/регистрируется → возвращается к оформлению → отправляет заявку → видит подтверждение.
