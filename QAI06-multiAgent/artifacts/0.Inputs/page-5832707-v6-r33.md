## §1. Требования (структурированный текст, без изменений)

### 1. Общие сведения
| Параметр | Значение |
|---|---|
| Название проекта | Лендинг «Мини-маркет» (MVP) |
| Тип | Веб-приложение (адаптивный лендинг) |
| Версия документа | 1.0 (draft) |
| Статус | На согласование |
| Владелец продукта | Product Owner |
| Бизнес-заказчик | Маркетинг / E-commerce |

### 2. Контекст и проблема
Нужен быстрый и недорогой MVP-лендинг для проверки спроса и сбора первых заказов.
Минимальный путь: зашёл → авторизовался → выбрал товары → добавил в корзину → оформил заявку.

### 3. Бизнес-цели
- BG-1: Проверить спрос → ≥ 100 оформленных заявок в первый месяц
- BG-2: Снизить барьер входа → конверсия «визит → авторизация» ≥ 25%
- BG-3: Понятный путь покупки → конверсия «корзина → заявка» ≥ 40%
- BG-4: Собрать контакты → ≥ 80% заявок с валидным телефоном

### 4. Границы проекта (Scope)
In Scope: авторизация (вход+регистрация); восстановление пароля; каталог; карточка товара;
корзина; оформление заявки (без онлайн-оплаты); адаптивность mobile-first, базовое SEO.
Out of Scope MVP: онлайн-платежи; личный кабинет с историей; мультипродавцовость/логистика/склад;
рекомендации/промо/лояльность; админ-панель товаров.

### 5. Стейкхолдеры
Product Owner; Маркетинг (заказчик); Покупатель (гость/авторизованный); Менеджер продаж;
Разработка/QA; Юрист/безопасность (комплаенс).

### 6. Функциональные бизнес-требования
- **FR-AUTH-1.** Гость видит каталог и может добавлять товары в корзину, но для оформления заявки обязан авторизоваться.
- **FR-AUTH-2.** Вход и регистрация по email + пароль.
- **FR-AUTH-3.** Валидация полей: корректный формат номера телефона, минимальная длина пароля, обязательные поля.
- **FR-AUTH-4.** Ошибки авторизации — понятным текстом без раскрытия внутренних деталей.
- **FR-AUTH-5.** После успешной авторизации — возврат к прерванному действию.
- **FR-AUTH-6.** Обязательное согласие на обработку ПДн (чекбокс + ссылка на политику).
- **FR-AUTH-7.** Кнопка восстановления пароля в окне авторизации с подтверждением сброса по номеру телефона пользователя.
- **FR-CAT-1.** Карточки товаров: фото, название, цена, кнопка «В корзину».
- **FR-CAT-2.** Статус доступности; недоступные нельзя добавить в корзину.
- **FR-CAT-3.** (Опционально MVP) Поиск по названию и базовая сортировка.
- **FR-CAT-4.** Переход на карточку товара с расширенным описанием.
- **FR-CART-1.** Добавление товара в корзину; повторное добавление увеличивает количество.
- **FR-CART-2.** Изменение количества и удаление позиции.
- **FR-CART-3.** Сумма по позициям и итоговая сумма.
- **FR-CART-4.** Сохранение корзины между сессиями; при авторизации привязывается к пользователю.
- **FR-CART-5.** Пустая корзина — понятное состояние с призывом вернуться к каталогу.
- **FR-CART-6.** Оформление заявки из корзины: сбор контактных данных и подтверждение.
- **FR-ORD-1.** Заявка содержит: состав корзины, итоговую сумму, контактные данные пользователя.
- **FR-ORD-2.** После отправки — подтверждение (экран/уведомление).
- **FR-ORD-3.** Заявка фиксируется для менеджера (email/таблица/админка — на усмотрение реализации).

### 8. Допущения и ограничения
Допущения: каталог до ~50 SKU, ручное обновление; без онлайн-оплаты; только email/пароль.
Ограничения: сжатые сроки и бюджет MVP; отсутствие интеграций (ERP, CRM) на старте.

### 9. Риски
Низкая конверсия авторизации (митигация: гостевой каталог); спам/фейковые заявки;
утечка ПДн; рост каталога ломает ручное управление.

### 10. Критерии приёмки MVP (бизнес-уровень)
1. Путь каталог → авторизация → корзина → заявка без ошибок.
2. Все ключевые события логируются.
3. Лендинг корректен на мобильных и десктопе.
4. Заявки доходят до менеджера с валидными контактными данными.
