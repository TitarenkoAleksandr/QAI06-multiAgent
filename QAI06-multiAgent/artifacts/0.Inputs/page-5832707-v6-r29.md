## 2. Контекст и проблема
Компании нужен быстрый и недорогой MVP-лендинг для проверки спроса на товары и сбора первых заказов. Полноценный маркетплейс (как Ozon) избыточен: нет логистики, платежей и продавцов. Нужен минимальный путь пользователя: зашёл → авторизовался → выбрал товары → добавил в корзину → оформил заявку.

## 4. Границы проекта (Scope)
**В скоупе (In Scope):**
- Окно/страница авторизации (вход + регистрация).

- Карточка товара (базовая).
- Корзина (добавление, изменение количества, удаление, итог).
- Оформление заявки (без онлайн-оплаты — заявка/самовывоз/менеджер).
- Адаптивность (mobile-first), базовое SEO лендинга.

**Вне скоупа (Out of Scope) для MVP:**
- Онлайн-платежи, эквайринг.
- Личный кабинет с историей заказов (только базовая авторизация).
- Мультипродавцовость, логистика, складской учёт.
- Рекомендации, промо-акции, программы лояльности.
- Админ-панель управления товарами (на старте — фиксированный каталог/ручное обновление).

## 6. Функциональные бизнес-требования

### 6.1 Авторизация
- FR-AUTH-1. Гость видит каталог и может добавлять товары в корзину, но для оформления заявки обязан авторизоваться.
- FR-AUTH-2. Регистрация и вход по email + пароль и регистрация нового пользователя.
- FR-AUTH-3. Валидация полей: корректный формат номера телефона, минимальная длина пароля, обязательные поля.
- FR-AUTH-4. Ошибки авторизации отображаются понятным текстом без раскрытия внутренних деталей.
- FR-AUTH-5. После успешной авторизации пользователь возвращается к прерванному действию (например, к оформлению корзины).
- FR-AUTH-6. Обязательное согласие на обработку персональных данных (чекбокс, ссылка на политику).
- FR-AUTH-7. Кнопка восстановления пароля в окне авторизации с подтерждением сброса **по номеру телефона** пользователя.

### 6.2 Каталог товаров
- FR-CAT-1. Отображение набора товаров в виде карточек: фото, название, цена, кнопка «В корзину».
- FR-CAT-2. Товары имеют статус доступности (в наличии / нет в наличии); недоступные нельзя добавить в корзину.
- FR-CAT-3. (Опционально MVP) Поиск по названию и базовая сортировка (цена/название).
- FR-CAT-4. Переход на карточку товара с расширенным описанием.

### 6.3 Корзина
- FR-CART-1. Пользователь добавляет товар в корзину; количество увеличивается при повторном добавлении.
- FR-CART-2. Можно изменить количество и удалить позицию.
- FR-CART-3. Корзина отображает сумму по позициям и итоговую сумму.
- FR-CART-4. Корзина сохраняется между сессиями (минимум — в рамках браузера; при авторизации привязывается к пользователю).
- FR-CART-5. Пустая корзина показывает понятное состояние с призывом вернуться к каталогу.
- FR-CART-6. Оформление заявки из корзины: сбор контактных данных и подтверждение.

### 6.4 Оформление заявки
- FR-ORD-1. Заявка содержит: состав корзины, итоговую сумму, контактные данные пользователя.
- FR-ORD-2. После отправки пользователь получает подтверждение (экран/уведомление).
- FR-ORD-3. Заявка фиксируется для менеджера (email/таблица/простая админка — на усмотрение реализации).

## 8. Допущения и ограничения
**Допущения:**
- Каталог на старте небольшой (до ~50 SKU) и обновляется вручную.
- Онлайн-оплата не требуется — заявка обрабатывается менеджером.
- Достаточно базовой авторизации (email/пароль), без соцсетей.

**Ограничения:**
- Сжатые сроки и бюджет MVP.
- Отсутствие интеграций с внешними системами (ERP, CRM) на старте.

## 9. Риски
| Риск | Влияние | Митигация |
|---|---|---|
| Низкая конверсия авторизации | Высокое | Гостевой каталог, авторизация только на этапе заявки |
| Спам/фейковые заявки | Среднее | Валидация, капча на отправке |
| Утечка ПДн | Высокое | Шифрование, комплаенс, аудит |
| Рост каталога ломает ручное управление | Среднее | Заложить простую админку/импорт на след. этапе |

## 10. Критерии приёмки MVP (бизнес-уровень)
MVP считается успешным, если:
1. Пользователь может пройти путь: каталог → авторизация → корзина → заявка без ошибок.
2. Все ключевые события логируются и доступны для анализа.
3. Лендинг корректен на мобильных и десктопе.
4. Заявки доходят до менеджера с валидными контактными данными.
