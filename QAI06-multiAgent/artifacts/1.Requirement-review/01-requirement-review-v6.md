**Контекст (§2):** нужен быстрый и недорогой MVP-лендинг для проверки спроса на товары и сбора первых заказов; полноценный маркетплейс избыточен (нет логистики, платежей, продавцов). Минимальный путь пользователя: зашёл → авторизовался → выбрал товары → добавил в корзину → оформил заявку.

**Бизнес-цели и KPI (§3):**

| ID | Цель | Метрика успеха (KPI) |
|---|---|---|
| BG-1 | Проверить спрос на товары через лендинг | ≥ 100 оформленных заявок в первый месяц |
| BG-2 | Снизить барьер входа для покупателя | Конверсия «визит → авторизация» ≥ 25% |
| BG-3 | Обеспечить понятный путь покупки | Конверсия «корзина → заявка» ≥ 40% |
| BG-4 | Собрать контактные данные для повторных продаж | ≥ 80% заявок с валидным телефоном/email |

**Стейкхолдеры (§5):** Product Owner (скорость запуска, метрики); Маркетинг (конверсия, сбор лидов); Покупатель гость/авторизованный (простота, скорость); Менеджер продаж (полные и валидные данные); Разработка/QA (чёткие требования); Юрист/безопасность (комплаенс, согласие на обработку ПДн).

**Направления функциональности (§4, §6):** Авторизация; Каталог товаров; Карточка товара; Корзина; Оформление заявки. Вспомогательные: поиск/сортировка (опционально), адаптивность/SEO, логирование, базовая доступность.

### 5.1. §10 «Критерии приёмки MVP (бизнес-уровень)» — дословно

> MVP считается успешным, если:
> - Пользователь может пройти путь: каталог → авторизация → корзина → заявка без ошибок.
> - Все ключевые события логируются и доступны для анализа.
> - Лендинг корректен на мобильных и десктопе.

### 5.2. Производный сценарий (НЕ документирован в требованиях)

- **UC-D1 (производный, ориентир, не требование):** посетитель открывает лендинг → просматривает каталог → открывает карточку товара → добавляет товары в корзину → переходит к оформлению → авторизуется/регистрируется → возвращается к оформлению → отправляет заявку → видит подтверждение.

### 5.3. Соответствие сценариев требованиям

Полноценная проверка **невозможна** из-за отсутствия раздела Use Cases (DEF-15). UC-D1 **не противоречит** REQ-1 – REQ-19, но **не покрывает**: повторное добавление товара (REQ-11), изменение количества/удаление (REQ-12), недоступный товар (REQ-8), пустую корзину (REQ-15), сохранение корзины между сессиями (REQ-14), отказ от согласия на ПДн (REQ-6), восстановление пароля (в требованиях отсутствует — DEF-09). Дополнительных условий/правил, противоречащих требованиям, в §10 **не обнаружено**.
