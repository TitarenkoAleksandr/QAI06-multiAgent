## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название проекта | Лендинг «Мини-маркет» (MVP) |
| Основное направление проекта | Электронная коммерция: сбор заявок на товары через лендинг (без онлайн-оплаты) |
| Тип проекта | **Web** (адаптивный лендинг, mobile-first) |
| Код проекта | В документе **не указан** → DEF-30 |
| Версия документа | 1.0 (draft) |
| Статус документа | На согласование (черновик, не утверждён) |
| Бизнес-заказчик | Маркетинг / E-commerce |

**Контекст (раздел 2, дословно):** «Компании нужен **быстрый и недорогой MVP-лендинг** для проверки спроса на товары и сбора первых заказов. Полноценный маркетплейс (как Ozon) избыточен: нет логистики, платежей и продавцов. Нужен минимальный путь пользователя: **зашёл → авторизовался → выбрал товары → добавил в корзину → оформил заявку**.»

**Бизнес-цели (раздел 3):**

| ID | Цель | KPI |
|---|---|---|
| BG-1 | Проверить спрос на товары через лендинг | ≥ 100 оформленных заявок в первый месяц |
| BG-2 | Снизить барьер входа для покупателя | Конверсия «визит → авторизация» ≥ 25% |
| BG-3 | Обеспечить понятный путь покупки | Конверсия «корзина → заявка» ≥ 40% |
| BG-4 | Собрать контактные данные для повторных продаж | ≥ 80% заявок с валидным телефоном/email (→ трактовка в §3.1) |

## 2. Исследуемая функциональность и требования

> Всего 58 REQ. Пометка `[OUT OF SCOPE MVP]` — решения пользователя от 2026-11-16 (см. `01a-user-decisions-v1.md`).

### 2.1. Авторизация и регистрация (FR-AUTH) — in scope
- **REQ-1** (FR-AUTH-1): Гость видит каталог и может добавлять товары в корзину.
- **REQ-2** (FR-AUTH-1): Для оформления заявки гость обязан авторизоваться.
- **REQ-3** (FR-AUTH-2): Вход по email + пароль.
- **REQ-4** (FR-AUTH-2): Регистрация нового пользователя.
- **REQ-5** (FR-AUTH-3): Валидация корректного формата email.
- **REQ-6** (FR-AUTH-3): Валидация минимальной длины пароля — *значение длины не задано* (DEF-15).
- **REQ-7** (FR-AUTH-3): Валидация обязательных полей.
- **REQ-8** (FR-AUTH-4): Ошибки авторизации отображаются понятным текстом.
- **REQ-9** (FR-AUTH-4): Ошибки авторизации не раскрывают внутренние детали.
- **REQ-10** (FR-AUTH-5): После успешной авторизации пользователь возвращается к прерванному действию.
- **REQ-11** (FR-AUTH-6): Чекбокс обязательного согласия на обработку ПДн.
- **REQ-12** (FR-AUTH-6): Ссылка на политику обработки ПДн.
- **REQ-13** (FR-AUTH-7): Кнопка восстановления пароля в окне авторизации.
- **REQ-14** (FR-AUTH-7): Сброс пароля выполняется через заявку на сброс пароля **на email**.

### 2.2. Каталог товаров (FR-CAT)
- **REQ-15** (FR-CAT-1): Отображение товаров в виде карточек.
- **REQ-16** (FR-CAT-1): Карточка содержит фото, название, цену и кнопку «В корзину».
- **REQ-17** (FR-CAT-2): Товар имеет статус доступности «в наличии / нет в наличии».
- **REQ-18** (FR-CAT-2): Недоступный товар нельзя добавить в корзину.
- **REQ-19** (FR-CAT-3): Поиск по названию товара. — **[OUT OF SCOPE MVP]**
- **REQ-20** (FR-CAT-3): Базовая сортировка по цене/названию. — **[OUT OF SCOPE MVP]**
- **REQ-21** (FR-CAT-4): Возможность перехода на карточку товара.
- **REQ-22** (FR-CAT-4): Карточка товара содержит расширенное описание.

### 2.3. Корзина (FR-CART) — in scope
- **REQ-23** (FR-CART-1): Добавление товара в корзину.
- **REQ-24** (FR-CART-1): Повторное добавление увеличивает количество позиции.
- **REQ-25** (FR-CART-2): Изменение количества позиции в корзине.
- **REQ-26** (FR-CART-2): Удаление позиции из корзины.
- **REQ-27** (FR-CART-3): Отображение суммы по каждой позиции.
- **REQ-28** (FR-CART-3): Отображение итоговой суммы корзины.
- **REQ-29** (FR-CART-4): Сохранение корзины между сессиями в рамках браузера.
- **REQ-30** (FR-CART-4): После авторизации корзина привязывается к пользователю.
- **REQ-31** (FR-CART-5): Пустая корзина показывает понятное состояние.
- **REQ-32** (FR-CART-5): Пустое состояние содержит призыв вернуться к каталогу.
- **REQ-33** (FR-CART-6): Оформление заявки запускается из корзины.
- **REQ-34** (FR-CART-6): При оформлении собираются контактные данные и требуется подтверждение.

### 2.4. Оформление заявки (FR-ORD) — in scope
- **REQ-35** (FR-ORD-1): Заявка содержит состав корзины.
- **REQ-36** (FR-ORD-1): Заявка содержит итоговую сумму.
- **REQ-37** (FR-ORD-1): Заявка содержит контактные данные пользователя. Телефон — **необязательное** поле; при заполнении валидируется формат.
- **REQ-38** (FR-ORD-2): После отправки пользователь получает подтверждение (экран или уведомление).
- **REQ-39** (FR-ORD-3): Заявка фиксируется для менеджера (способ — по допущению D-1).
- **REQ-40** (FR-ORD-3): Способ фиксации — email / таблица / простая админка — на усмотрение реализации.
