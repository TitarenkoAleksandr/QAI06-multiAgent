## 1. Бизнес-правила

- BR-1. Гость может просматривать каталог и добавлять товары в корзину; оформление заявки требует авторизации. *(FR-AUTH-1)*
- BR-2. Согласие на обработку ПДн обязательно. *(FR-AUTH-6, NFR-4)*
- BR-3. Товар «нет в наличии» нельзя добавить в корзину. *(FR-CAT-2)*
- BR-4. Повторное добавление товара увеличивает количество, а не создаёт дубль. *(FR-CART-1)*
- BR-5. Корзина сохраняется между сессиями; после авторизации привязывается к пользователю. *(FR-CART-4)*
- BR-6. После авторизации пользователь возвращается к прерванному действию. *(FR-AUTH-5)*
- BR-7. Ошибки авторизации не раскрывают внутренние детали. *(FR-AUTH-4)*
- BR-8. Онлайн-оплаты нет; заявка обрабатывается менеджером. *(§2, 4, 8)*
- BR-9. Авторизация — email + пароль, без соцсетей. *(§8)*
- BR-10. Восстановление пароля выполняется в отдельном окне, сброс — на email. *(уточнение пользователя + страница 7045122)*
- BR-11. Не раскрывается факт существования аккаунта с указанным email. *(7045122, §4)*
- BR-12. Ссылка сброса одноразовая, с ограниченным сроком жизни; повторная отправка ограничена интервалом 60 с. *(7045122, §2, §4)*
- BR-13. После успешного сброса все активные сессии пользователя завершаются. *(7045122, §2)*

- **UC-PR-1.** Пользователь открывает окно авторизации, нажимает «Восстановление пароля», вводит email, нажимает «Отправить ссылку», получает нейтральное подтверждение.
- **UC-PR-2.** Пользователь переходит по ссылке из письма, задаёт новый пароль; после успешного сброса старый пароль не работает, активные сессии завершаются.
- **UC-PR-3.** Пользователь повторяет запрос ранее чем через 60 с — получает сообщение «Попробуйте позже».
- **UC-PR-4.** Пользователь вводит пустой email или email неверного формата — получает сообщение валидации.
- **UC-PR-5.** Несуществующий email — поведение не отличается от существующего ( нейтральное сообщение).

- **REQ-15f** (7045122): ссылка из письма ведёт на страницу задания нового пароля.
