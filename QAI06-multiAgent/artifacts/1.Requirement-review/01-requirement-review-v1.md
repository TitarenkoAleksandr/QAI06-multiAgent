## Функциональность, направления и функции

### Базовая (основная) функциональность
- **Авторизация** — вход и регистрация пользователя (email + пароль)
- **Каталог товаров** — сетка карточек с товарами (фото, название, цена, кнопка «В корзину»)
- **Карточка товара** — расширенное описание товара
- **Корзина** — добавление/изменение/удаление товаров, расчёт суммы
- **Оформление заявки** — сбор контактных данных и отправка заявки менеджеру

### Сервисная и вспомогательная
- Поиск по названию и базовая сортировка (опционально MVP)
- Логирование ключевых событий (NFR-7)
- Базовая доступность (NFR-5)

### Особенности и фичи
- Работа без авторизации для просмотра каталога и корзины
- Привязка корзины к пользователю после авторизации
- Mobile-first адаптивность

## Требования

### Функциональные требования

#### 6.1 Авторизация

| ID | Требование |
|---|---|
| REQ-1 (FR-AUTH-1) | Гость видит каталог и может добавлять товары в корзину, но для оформления заявки обязан авторизоваться. |
| REQ-2 (FR-AUTH-2) | Поддерживается вход по email + пароль и регистрация нового пользователя. |
| REQ-3 (FR-AUTH-3) | Валидация полей: корректный формат email, минимальная длина пароля, обязательные поля. |
| REQ-4 (FR-AUTH-4) | Ошибки авторизации отображаются понятным текстом без раскрытия внутренних деталей. |
| REQ-5 (FR-AUTH-5) | После успешной авторизации пользователь возвращается к прерванному действию (например, к оформлению корзины). |
| REQ-6 (FR-AUTH-6) | Обязательное согласие на обработку персональных данных (чекбокс, ссылка на политику). |

#### 6.2 Каталог товаров

| ID | Требование |
|---|---|
| REQ-7 (FR-CAT-1) | Отображение набора товаров в виде карточек: фото, название, цена, кнопка «В корзину». |
| REQ-8 (FR-CAT-2) | Товары имеют статус доступности (в наличии / нет в наличии); недоступные нельзя добавить в корзину. |
| REQ-9 (FR-CAT-3) | (Опционально MVP) Поиск по названию и базовая сортировка (цена/название). |
| REQ-10 (FR-CAT-4) | Переход на карточку товара с расширенным описанием. |

#### 6.3 Корзина

| ID | Требование |
|---|---|
| REQ-11 (FR-CART-1) | Пользователь добавляет товар в корзину; количество увеличивается при повторном добавлении. |
| REQ-12 (FR-CART-2) | Можно изменить количество и удалить позицию. |
| REQ-13 (FR-CART-3) | Корзина отображает сумму по позициям и итоговую сумму. |
| REQ-14 (FR-CART-4) | Корзина сохраняется между сессиями (минимум — в рамках браузера; при авторизации привязывается к пользователю). |
| REQ-15 (FR-CART-5) | Пустая корзина показывает понятное состояние с призывом вернуться к каталогу. |
| REQ-16 (FR-CART-6) | Оформление заявки из корзины: сбор контактных данных и подтверждение. |

#### 6.4 Оформление заявки

| ID | Требование |
|---|---|
| REQ-17 (FR-ORD-1) | Заявка содержит: состав корзины, итоговую сумму, контактные данные пользователя. |
| REQ-18 (FR-ORD-2) | После отправки пользователь получает подтверждение (экран/уведомление). |
| REQ-19 (FR-ORD-3) | Заявка фиксируется для менеджера (email/таблица/простая админка — на усмотрение реализации). |

### Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| REQ-20 (NFR-1) | Производительность | Загрузка лендинга ≤ 3 с на 4G; отклик UI ≤ 500 мс |
| REQ-21 (NFR-2) | Адаптивность | Корректная работа на мобильных, планшетах, десктопе |
| REQ-22 (NFR-3) | Безопасность | Пароли хранятся хешированными; HTTPS; защита от базовых атак (XSS, CSRF) |

| REQ-24 (NFR-5) | Доступность | Базовая доступность (контраст, alt-тексты, клавиатурная навигация) |
| REQ-25 (NFR-6) | Масштабируемость | Готовность к росту каталога и трафика без переработки |
| REQ-26 (NFR-7) | Наблюдаемость | Логирование ключевых событий (авторизация, добавление в корзину, заявка) |

## Бизнес-правила

1. **BP-1:** Гость может просматривать каталог и добавлять товары в корзину, но оформление заявки доступно только авторизованному пользователю.
2. **BP-2:** Каталог на старте небольшой (до ~50 SKU) и обновляется вручную.
3. **BP-3:** Онлайн-оплата не требуется — заявка обрабатывается менеджером.
4. **BP-4:** Достаточно базовой авторизации (email/пароль), без соцсетей.
5. **BP-5:** Обязательное согласие на обработку ПДн (согласие + ссылка на политику).
6. **BP-6:** Пароли хранятся хешированными (NFR-3).

---

## Ограничения

1. **LIM-1:** Сжатые сроки и бюджет MVP.
2. **LIM-2:** Отсутствие интеграций с внешними системами (ERP, CRM) на старте.
3. **LIM-3:** Каталог на старте ~50 SKU, ручное обновление без админ-панели.
4. **LIM-4:** Только базовая авторизация (email/пароль), без соцсетей и OAuth.

## Критерии приёмки

Критерии приёмки MVP (раздел 10 документа):

| ID | Критерий |
|---|---|
| AC-1 | Пользователь может пройти путь: каталог → авторизация → корзина → заявка без ошибок. |
| AC-2 | Все ключевые события логируются и доступны для анализа. |
| AC-3 | Лендинг корректен на мобильных и десктопе. |
| AC-4 | Заявки доходят до менеджера с валидными контактными данными. |

## Заключение

Требования к лендингу «Мини-маркет» (MVP) в целом структурированы, выделены функциональные и нефункциональные группы, бизнес-цели, ограничения и риски. Однако документ имеет **1 Blocker** и **10+ Major/Minor** дефектов, включая отсутствие критически важных разделов (восстановление пароля, обработка ошибок, пользовательские сценарии).

**Quality Gate QG-1: FAIL** — наличие Blocker-проблемы (DEF-09) блокирует переход к проектированию задач и тестов.

**Рекомендуемые действия:**
1. Добавить описание процесса восстановления пароля (обязательно).
2. Устранить неоднозначности DEF-03–DEF-08.
3. Добавить недостающие разделы (обработка ошибок, user scenarios, антиспам/капча).
4. Согласовать статус опциональных функций (FR-CAT-3).
