### 0.1. Решение пользователя, влияющее на тест-дизайн (вход прогона)

- Требования **не изменялись** (страница Confluence 2129922, version 3).
- DEF-09 (нет описания восстановления пароля) переклассифицирован **Blocker → Major** и принимается как известное ограничение.
- **Следствие:** сценарии восстановления пароля **не проектируются** как проверки несуществующего требования. Механизм сброса, сроки жизни ссылки/кода, требования к новому паролю **не выдумываются**. В настоящем артефакте такие места зафиксированы как `open_questions` (TC-9, TC-10 — требования к паролю; отдельного кейса «восстановление пароля» нет, т.к. проверять нечего).

## 1. Подход к проектированию

| Приём | Где применён |
|---|---|
| Классы эквивалентности | валидация email (TC-8), пароль (TC-9, TC-10), телефон (TC-49, TC-50) |
| Граничные значения | пароль на границе минимальной длины (TC-9/TC-10), количество = 0 (TC-33), лимиты корзины (TC-34, TC-35), TTL корзины (TC-42), объём каталога ~50 SKU (TC-19), повторная отправка (TC-54), нагрузочная граница (TC-73) |
| Таблица решений | доступность товара × точка входа в корзину (TC-20, TC-21, TC-27, TC-29), согласие ПДн × регистрация (TC-15, TC-16) |
| Состояния и переходы | гость → авторизация → возврат к действию (TC-2, TC-13, TC-14), корзина гость → пользователь (TC-41), пустая/непустая корзина (TC-43, TC-45) |
| Попарное покрытие (pairwise) | матрица устройств (TC-60…TC-62), браузеры/ОС (TC-63) |
| Негативное тестирование | ошибки авторизации (TC-5…TC-8, TC-11, TC-12), ошибки заявки (TC-47, TC-48, TC-50, TC-55), безопасность (TC-66, TC-67) |

**Правило «один кейс — один объект проверки»:** каждый кейс имеет один основной проверяемый объект; несколько REQ в поле `requirements` означают совместную проверку связанных требований в одном сценарии, а не дублирование (см. §7).

**TC-1 · `positive` · S-1**
- **title:** Гость просматривает каталог и добавляет товар в корзину без авторизации
- **preconditions:** Пользователь не авторизован (активной сессии нет). Каталог содержит товар со статусом «в наличии».
- **data:** Товар — доступный SKU из каталога MVP; учётные данные не требуются.
- **steps:**
  1. Открыть лендинг «Мини-маркет».
  2. Дождаться загрузки каталога.
  3. Нажать «В корзину» на карточке доступного товара.
  4. Открыть корзину.
- **expected result:** Каталог доступен неавторизованному пользователю; товар добавлен в корзину (1 позиция); запрос авторизации при добавлении не возникает; пользователь остаётся неавторизованным.
- **requirements:** REQ-1
- **open_questions:** —

**TC-2 · `negative` · S-1**
- **title:** Гость не может оформить заявку без авторизации
- **preconditions:** Пользователь не авторизован. В корзине ≥ 1 товар.
- **data:** —
- **steps:**
  1. Открыть корзину.
  2. Нажать «Оформить заявку».
  3. Проверить результат действия.
- **expected result:** Заявка **не создаётся**; система требует авторизации (переход на форму входа/регистрации либо запрос входа); содержимое корзины сохраняется.
- **requirements:** REQ-1
- **open_questions:** Форма требования авторизации (редирект на страницу или модальное окно) в требованиях не задана — DEF-15; проверяется только инвариант «заявка не создана, корзина сохранена».
